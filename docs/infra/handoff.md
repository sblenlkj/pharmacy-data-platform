# Инфраструктурная часть: передача и текущее состояние

Изначально инфраструктура (HA-стенд, Patroni/etcd/HAProxy/PgBouncer, Compose,
манифесты) готовилась в отдельной ветке и передавалась команде отдельным
патчем. Сейчас она влита в основной репозиторий (merge PR #2) и является
рабочей частью проекта; этот документ фиксирует действующие договорённости и
текущий статус.

## Текущее состояние

- HA-стенд целиком собирается одной командой `docker compose up -d --build`
  и проверяется `./scripts/wait_ready.sh` (топология, роли RW/RO, контрактные
  представления, догон реплик).
- Эксперименты отказоустойчивости Э1–Э7 выполнены на реальном стенде
  2026-10-18: команды, raw-логи и измерения — в
  [docs/failover_journal.md](../failover_journal.md) и
  [reports/failover/](../../reports/failover/).
- Официальный чекер проходит 17/21; единственное расхождение `ha.running`
  (чекер ждёт `state=running`, здоровые реплики Patroni ≥ 3.0.4 отдают
  `streaming`) — проблема чекера, а не стенда; преподаватель подтвердил и
  поправит чекер, подробности в
  [checker-compatibility.md](checker-compatibility.md).
- Детерминизм и идемпотентность генератора проверены на двух чистых стендах.

## Действующие договорённости

1. Имена четырёх `*_service_db` и контракт `contract.*` неизменны.
2. Исправления схемы — только новыми нумерованными SQL-файлами в
   `migrations/<service>/`; каждый файл транзакционный (без внутренних COMMIT,
   CREATE DATABASE, CREATE INDEX CONCURRENTLY). Изменённый уже применённый
   файл вызовет ошибку по SHA-256 в `infra.schema_migrations`.
3. Генератор остаётся вызываемым как `python -m pharmacy_dwh.seed.cli`;
   инфраструктурные обёртки (`scripts/seed.sh`, `scripts/infra/seed.py`)
   маршрутизируют его через RW-пул.
4. Права `app` — DML бизнес-таблиц; новая логика, требующая дополнительных
   schema/function привилегий, добавляет их в `configure_access_and_cdc`
   (`scripts/infra/bootstrap.py`).
5. `db-init` всегда ходит к лидеру через HAProxy RW-порт и переустанавливает
   права/публикации идемпотентно при каждом запуске.

## Как расширять

- Новая миграция: добавить файл → `./scripts/migrate.sh` →
  `./scripts/wait_ready.sh`. Подробнее — [README](../../README.md).
- Изменения Python-кода и миграций видны через bind-mount без пересборки;
  Dockerfile/requirements/конфиги образов — только с `--build`.
- Параметры `bootstrap.dcs` после первого старта меняются через
  `patronictl edit-config`, а не только правкой YAML.

Рабочие предметные заметки и отложенные улучшения — в
